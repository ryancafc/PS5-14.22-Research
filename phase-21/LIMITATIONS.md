# Limits and outstanding evidence

- Historical 14.10 returned an empty object at the checked official URLs. No 14.10 pair comparison or associated 117-byte count was reproduced. Optional 14.10/14.20 recovery packages were not requested or downloaded.
- Metadata/checksum attribution uses pinned community records, archived Sony XML and successful official-host delivery; Sony signatures and an internal protected version field were not independently authenticated. Empty HTTP 200 is not availability.
- Only SLB2 v3 is supported. Bounds/count/version errors reject the package with exit status 2. Gaps are measured, but unknown header-extension bytes are not assumed padding. Entropy is sampled with explicit offsets, not whole-file proof of encryption. Protected entries are hashed, never decrypted or executed.
- Phase 20 evidence classes remain unchanged. New evidence resolves specific prior availability blockers only for the inputs now obtained. It cannot retrospectively turn mock chain results into hardware evidence.
- Ghidra breadth is partial: the new ABI 2 sample is ET_DYN, not a second accepted SCE executable. No ABI 3 or alternate SCE dynlib-data layout was validated. All four targets are x86-64; the FreeBSD object and System V linked control are compiler-generated. No header spoofing occurred.
- Selected Ghidra decompilation success is not all-function correctness. Baseline warnings remain; real console import execution and library implementations were not tested. External symbol records, actual libraries and function records are different counts.
- Chromium and Firefox results apply to their exact recorded desktop versions and loopback contexts. No WebKit engine or PS5 console test occurred. Four normal runs contain repeated checks; harness controls/replays are separate, not independent exploit evidence. The UNSUPPORTED code path exists, but no artificial API deletion is presented as a native-engine result.
- Browser resource limits bound the suite's explicit work, not total browser process memory. No stress, allocation ceiling, memory-corruption trigger or exploit chain was run. The harness uses installed system binaries, not Playwright-specific patched Firefox.
- The research-status workflow was source-reviewed and one existing successful main push run observed. Phase 21 does not trigger or modify that workflow. No unsupported numerical jailbreak probability is produced: UNKNOWN remains.
- Publication is a separate reviewed update stacked on the still-pending Phase 20 branch; it does not silently merge or overwrite pending work. Private paths are sanitized in the public subset; firmware, binary samples, external release archives, Ghidra databases and private keys are excluded. Original benign tools are MIT licensed; upstream binaries are linked with provenance, not redistributed.
